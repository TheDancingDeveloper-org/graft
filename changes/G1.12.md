# G1.12: server binary

- `graft-server serve`: the four `graft.v1` gRPC services over the engine on the SQLite and filesystem stores, gzip both ways, plus `/healthz`, `/readyz`, `/metrics` and a read-only JSON facade under `/v1` on the same listener (and `/metrics` on an optional second `metrics` listener). Every call authenticates a bearer PASETO token (`authorization: Bearer …`) and binds the `graft-protocol` version; the engine checks scopes per operation, so refusals are typed `Unauthenticated`, `IncompatibleProtocol` or `PermissionDenied`. Writes are refused with `Unavailable` below the free-space floor (`min_free_fraction`, `min_free_bytes`); reads continue. SIGTERM or SIGINT drains gracefully. Operations the engine has not built yet (log, blame, ancestry, rebase, land, workspaces, GC) answer `Unimplemented` (HTTP 501) instead of failing the connection. `MintToken` mints tokens no broader than the caller's, capped by `max_token_ttl_s`.
- TOML config (`--config`, `$GRAFT_SERVER_CONFIG`, else `/etc/graft/server.toml`); unknown keys are refused. The signing key is created on first use beside the database.
- `graft-server admin`: `token mint`, `repo create` (both safe while the server runs), `fsck` (every journalled changeset, its parents and its whole snapshot, plus refs; run with the server stopped), and `backup <dir> [--objects]` (SQLite `VACUUM INTO`, then an incremental object copy).
- Process-level tests start the binary: import a synthetic repository through the API, `kill -9`, restart, fetch and verify everything, fsck clean; corrupt-object detection and a backup restored clean; refusals; health, metrics and the facade; the admission floor; restart to serving under 2 s.
