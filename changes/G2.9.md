# G2.9: GC index ports (partial; `Gc` is refused)

- `graft-store`: `MetaStore::list_records(repo, state, after, limit)` pages changesets in one record state, in id order. `MetaStore::holder_rows(repo, object, after, limit)` pages the holder names of one object, in name order. Both default to `StoreError::Backend` until a store implements them. The memory store and the SQLite store implement them, and the conformance suite checks paging, state filtering, repository isolation and resume-after on both.
- `graft-store-sqlite`: schema version 3 adds `changesets_state_id (repo, state, id)`, so `list_records` reads one state without sorting. `holder_rows` uses the holders primary key.
- `graft-engine`: `Gc` answers `Rejected { policy: "gc" }` for both a dry run and a sweep. Nothing reachable from the admin API deletes. The dry-run report (`docs/design.md` §8.6) waits on a design decision, because the holder rows do not yet protect an object that a live changeset references without introducing it.
