# WI-2220: server metrics for the writer queue, store timing and free disk

- `graft-store-sqlite`: new `StoreObserver` trait, installed with `SqliteMetaStore::open_observed`. The store reports the writer queue depth each time a job is queued or taken, and each `MetaStore` operation's latency measured from the call (queueing included). The store does not depend on telemetry; `open` is unchanged and passes no observer.
- `graft-server`: the observer records `graft_sqlite_writer_queue_depth` and `graft_store_op_seconds{port="meta",op}`. These were registered but never set, so the ops alert `GraftSqliteWriterSaturated` could not fire.
- `graft-server`: the free-space floor's `statvfs` reads now set `graft_disk_free_bytes{volume}` and `graft_disk_total_bytes{volume}` (`objects` and `meta`). A scrape of `/metrics` refreshes them, so the gauges are current without writes.
- `graft-telemetry`: the two disk gauges are registered. They are not yet in design §13.
- Test: the API test, after its writes, scrapes `/metrics` and checks the store timing, queue depth and both disk gauges.
- Not changed: the mirror config under `docker/dev`, and the object store's `graft_store_op_seconds` (`port="objects"`).
