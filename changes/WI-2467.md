## graft-node cache restart no longer races the store lock

`NodeRun::stop` aborted the task that accepts connections. Tonic serves each
connection on a task of its own, spawned from that accept task and holding a
clone of the node, so the cache store's exclusive `flock` outlived the stop.
The next `Node::open` of the same cache then panicked with "objects is in use
by another process" (`cache::with_upstream_down_cached_reads_work_and_misses_fail_fast`,
PR #198). `stop` now joins the serve task, which returns only after those
connection tasks have dropped the lock. Callers drop their client first, so
nothing keeps a connection open.

## `import_kill9_restart_fetch_fsck` is quarantined

The ~75s kill-9 e2e failed once on an unrelated merge-queue run (PR #196) and
passed on retry. It is `#[ignore]`d, so the required nextest run skips it, and
a merge-queue-only slow step still runs it. See `docs/known-flakes.md`.
