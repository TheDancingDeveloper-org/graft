## graft-node tests wait for the cache lock

`with_upstream_down_cached_reads_work_and_misses_fail_fast` reopens the same
cache after `NodeRun::stop`. The store's exclusive `flock` on
`cache/objects/.lock` lives as long as any `Node` clone, including the test's
own `NodeRun`, so joining the serve task does not free it. The next
`Node::open` then panics with "objects is in use by another process" (PR #198,
run 2). After dropping the run, the test now waits (5s) until a non-blocking
exclusive lock on that file succeeds, then releases it, which is the same
check the next open makes. `stop` keeps its 5s timeout.

## `import_kill9_restart_fetch_fsck` is quarantined

The ~75s kill-9 e2e failed once on an unrelated merge-queue run (PR #196) and
passed on retry. It is `#[ignore]`d, so the required nextest run skips it. A
separate non-required `slow` job (`continue-on-error`) runs it on
`merge_group` only. Follow-up: WI-2469. See `docs/known-flakes.md`.
