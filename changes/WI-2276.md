# WI-2276: trial attester on the graft-dev VM

- New crate `graft-attester` (lib + bin). It watches one repository's journal for drafts held by a workspace. It keeps the newest draft per workspace in a bounded queue, and the journal holds the overflow. It checks one draft at a time: it confirms the changeset is still a draft, checks the tree out with `graft-client`, runs the configured checks (default `ci/build=cargo build --locked`, `ci/test=cargo test --locked`), and posts `Attest` per check, passed or failed, with the log's path as the URL. Each check runs in its own process group with a cleared environment, a timeout and a capped log, optionally as another uid (`--run-as`), and after a failure the later checks are attested failed without running. The read position persists across restarts. The token is read from a 0600 file and never printed.
- No silent failures (review of 64a566d): a checkout that fails transiently is retried up to `max_attempts`, then every check is attested failed. A permanent checkout failure attests every check failed at once, with a log saying why. `Attest` is retried with backoff. If it still fails, the results are kept and the draft is requeued, so the attestations are posted again without re-running the checks.
- `deploy/`: an opt-in `graft-attester` service, compose profile `attester`, built from `deploy/attester/Dockerfile` (Rust 1.99 runtime for rustTorrent). It runs as root with only CHOWN/SETUID/SETGID/KILL and runs the checks as uid 10001, so a check can't read the token. CPU, memory and process caps apply, and the logs and cargo cache live in volumes. With `GRAFT_ATTESTER=1`, `up.sh` creates `rusttorrent-trial`, mints `/etc/graft/attester-token` (`read` + `attest`, root-owned 0600, renewed like the mirror token), and builds and starts the attester. See `deploy/README.md`.
- Needs the `attest` scope from WI-2272 on the server. Until then, minting the attester token fails, and that only matters with the profile on.
- Smoke test (`crates/graft-attester/tests/smoke.rs`): the engine behind `TestServer` with a tiny repository. A passing draft gets two passing attestations, a failing draft a failing one, a check past its timeout is killed and failed, and a draft that is no longer a draft is skipped. Injected faults cover checkout retry and give-up, permanent checkout failure, and Attest retry without re-running the checks.
