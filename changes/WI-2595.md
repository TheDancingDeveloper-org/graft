graft-engine implements `ReviewQueue`: the landings on a line after `since_lsn` with no `review` attestation, in LSN order, with each landing's author, paths touched and lines changed, filtered by `path_prefix` and `max_lines`, paged with `next_lsn` (pass it back as `since_lsn`; `None` when caught up; a page token is rejected). Every land that moves a line, on any line whatever its `checks` setting, now indexes the landing in the store's review queue and writes a `land-summary` derived value (first position, paths, lines) in its own transaction; a land that moves nothing adds neither. A `review` attestation of any status takes the landing out; `check` and `approval` leave it. Lines changed are exact for text within the patch input cap; a larger text side counts its size in bytes (an upper bound) and binary counts none. The path filter reads the line path index, one indexed read per landing. A call reads at most `MAX_REVIEW_SCAN` (4,000) queue rows, the page included, never the line or the journal. It needs `repo:<r>:read` and never affects landing.
