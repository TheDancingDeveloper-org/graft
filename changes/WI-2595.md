graft-engine implements `ReviewQueue`: the landings on a line after `since_lsn` with no `review` attestation, in LSN order, with each landing's author, paths touched and lines changed, filtered by `path_prefix` and `max_lines`, paged with `next_lsn` (pass it back as `since_lsn`; `None` when caught up; a page token is rejected). Every land that moves a line, on any line whatever its `checks` setting, now writes only the store's review queue index row (position, LSN, changeset); the land computes nothing for the queue and reads no blob. A `review` attestation of any status takes the landing out; `check` and `approval` leave it. Summaries are computed when the queue is read: the land's old tip from its own `RefMoved` entry (a point read at the row's LSN), one id-pruned tree diff and the changed blobs, then cached as a `land-summary` derived value. When those objects are missing or corrupt the item reports `PATHS_UNAVAILABLE` / `LINES_UNAVAILABLE` (a `max_lines` filter leaves it out) and the rest of the page is answered. Lines are exact for text within the patch input cap; a larger text side counts its size in bytes (an upper bound) and binary counts none. The path filter reads the line path index and needs no blob. A call reads at most `MAX_REVIEW_SCAN` (4,000) queue rows, the page included, never the line or the journal. It needs `repo:<r>:read` and never affects landing.
